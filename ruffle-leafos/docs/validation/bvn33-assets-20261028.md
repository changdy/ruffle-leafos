# 死神 VS 火影 3.3：脚本优化版的素材优化副本

日期：2026-10-28。以已验证的[四方法脚本优化版](bvn33-swf-patch-20261027.md)为输入，按[2.6 / 3.3 对比分析](bvn26-vs33-20261028.md)继续处理外部素材。本轮生成独立的完整目录；原离线版、原脚本优化版和播放器保留，没有减少出招/碰撞帧、AI 更新频率或特效数量，也没有将默认战斗帧率降至 30。

## 实际修改

目录名为 `死神VS火影3.3-脚本素材优化版`，主文件与相邻 `assets/` 必须一起使用。

- 检查主电影及 91 个外部 SWF，共 92 个电影、81 个 ABC；常量池和 ABC 原字节未检出 readGraphicsData / GraphicsBitmapFill 名称。结合现有反编译路径，没有发现通过这些接口读取/修改内部填充位图的用法。这不是对动态拼接属性名或未来外部代码的形式化证明。
- 为素材优化器增加显式 `--avm2-private-bitmaps`；默认仍拒绝 AVM2。保留导出位图、直接放置位图及其他引用保护；裁剪跳过平铺填充、非整数 twip 补偿和无法安全解析的结构。同步补偿形状填充矩阵，保留原几何与碰撞范围。
- 91 个外部 SWF 中 76 个改变，均为 AVM2；共裁剪 **10,232** 张私有无损位图，合并 **1,017** 个重复定义。另 15 个 SWF 和 307 个非 SWF 资源保留原字节。
- 主 SWF 保留原四方法补丁和全部 ABC，只新增标识此实验副本的 XML Metadata，并设置对应 HasMetadata 位。其帧头、时间轴及其他标签保持。新内容身份使原生进度独立，不自动迁移旧版进度。

## 主机验证

- 9 项格式/保护回归通过，覆盖原 AVM1 路径、AVM2 默认拒绝、显式允许后保留 ABC/SymbolClass/导出位图、私有位图去重及遇到图形数据反射接口时拒绝处理。
- 对 91 个资源的 **14,729** 个原始位图定义逐行还原、逐像素比较；裁剪外区域必须全零，去重目标也按原位置还原比较。**16,231** 个形状的几何和非填充字段一致，**23,843** 个填充的 ID 映射及整数矩阵补偿核验通过。
- 全部 ABC、SymbolClass、帧标签、放置、声音等非编辑标签原字节一致，Sprite 的 ID/声明帧数保持；受保护位图的定义字节保持。主文件单独核验仅 Metadata/HasMetadata 变化，原四方法脚本字节保持。
- 使用对应仓库的 Ruffle SWF 解析器，184 个原始/候选 SWF 全部解析通过。工具为既有本地主机校验程序，没有重编译或更新正式播放器。

像素还原与矩阵检查验证资源变换，不等同全角色视觉/事件兼容验收；实机范围另列。

## 实机对照

复用同一 Pocket1 和已安装播放器，显式 GLES、独立 HOME/按键/原生进度，游戏内部 MEDIUM、默认 60 FPS。选择单人对 CPU、一护/鸣人、魂/我爱罗和空座町；每组输入 `right,a,y,a,b,a,x,a` 六遍，共 48 次物理点击，点击约 120 ms 后等待 250 ms。AI、随机数、动作和温度没有逐帧锁定，结果不作为严格加速比。

先依次完成旧脚本版一、新素材版一、新素材版二；仅选非暂停、目标 60 FPS 的窗口，核对所选窗口内没有选人、选图或加载切换。新素材版二完成后在选人页检查暂停/继续，两次候选及首组基线均正常退出，日志 `progress_flushed=true`。原计划的旧版第二次会话因设备电量耗尽中断，未取得战斗数据，独立保存为失败会话，不算性能样本。

用户充电后提供新地址继续，成功重连同一设备，在 `baseline-2-resumed` 独立会话补齐第四组。条件和输入相同，仍核对没有选人/加载切换，并正常退出；本次首尾离散 CPU 为 1.8 / 1.992 GHz、温度约 53.1 / 55°C。第四组与前三组之间经历断电、重启和充电，不能当作环境严格一致的连续 ABBA 实验。
