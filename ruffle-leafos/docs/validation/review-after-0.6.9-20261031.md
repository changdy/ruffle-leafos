## 主要结论

未确认需要本次立即修改的高置信运行代码缺陷。确认以下历史问题和边界，不能将“最终已有修复”写成“最初提交没有问题”：

| 问题 | 引入或暴露阶段 | 最终状态 |
| --- | --- | --- |
| Vulkan 形状不持有原始 BitmapHandle，弱位图缓存失效并重复上传 | `54ed493` 弱引用资源策略与 Vulkan 接入组合 | `1e2461d` 为待完成和最终形状保留句柄，避免直接 BitmapData 自引用；本轮 3 项 wgpu noop 所有权回归通过 |
| CLI/Apps 临时 renderer 选择污染保存偏好 | `1a5d7b2` 的双后端配置路径 | `1e2461d` 分离请求/实际接口与持久偏好；当前全局设置沿用这一规则 |
| 英语菜单残留中文语言标题 | `fdbe41f` 初始国际化 | `a8f893a` 修复，当前翻译调用与表项核对未见静态缺键 |
| 仅改槽默认值却宣称死神首次启动 LOW | `f9f210e` 的历史交付说明 | `56e9c4c` 更正了文档；已提交游戏入口仍覆盖为 MEDIUM，LOW 需手动选择。工作区另有既有未提交修复，不算本次完成 |
| 静态缓存预算没有覆盖滤镜 scratch 的按尺寸无限保留 | `ea09c15` 的预算覆盖边界，池路径此前已存在 | `1a0255a` 为闲置纹理和 PBO 分别限容；活动/在途资源与总 GPU/RSS 仍不受该闲置预算限制 |

仍应保留的工程风险：本地打包使用现成 ELF。`build_player.py` 的构建记录绑定 ELF SHA 和编译参数，`package_preview.py` 分别检查该 SHA 与当前源码锁；**没有将构建时源码摘要绑定到该 ELF**。因此构建后修改源码并更新来源锁，再直接打包，现有检查不能证明 ELF 对应新源码。此路径在 0.6.9 时已有，自动 Release 每次重建；本次记录为后续加固项，未修改实现，也未重新生成发布包。定位见[构建记录](../../scripts/build_player.py)与[打包检查](../../scripts/package_preview.py)。

Vulkan 跨 API 同步、真实 GPU 像素、全角色/长时 OOM、断电/休眠和多卡仍依赖硬件验证；本轮通过主机测试不能关闭这些待办。当前设计的合理性建立在既有有限场景与保守降级规则上，不是完整兼容性保证。
