# 死神 VS 火影 3.3：SWF 脚本优化实验副本

日期：2026-10-27。用户授权直接修改现有离线版 SWF，并已选择稍后再做设备测试。本轮生成独立的完整游戏目录与 ZIP，仅修改主 SWF 的四个方法；没有修改或安装播放器，也没有覆盖原可玩离线版。它是待 Pocket1 验证的实验副本，尚无实机帧率或卡顿改善结论。

## 实际修改

| 方法 | 改动 | 保留的行为 |
| --- | --- | --- |
| `FightTimeUI.render` | 仅当 `_numMc.number` 与当前整数秒数不同时执行数字 setter，避免同一秒内反复删除和创建数字 MovieClip | 构造函数首次显示、无限时间分支、倒计时计算及结束判定 |
| `QiBar` 内部 `InsBar.setProcess` | 气槽数字的目标帧与 `currentFrame` 不同时才 `gotoAndStop`，相同时调用 `stop` | 连续气量、插值、气条宽度和可见性、实际档位切换、数字停止状态 |
| `FighterAILogicBase.targetInRange` | 用 `Rectangle.intersects` 替换仅用于布尔判断的 `intersection(...).isEmpty() == false` | 原有空目标/空攻击框检查、范围、AI 调用频率和决策顺序 |
| `GameMainLogicCtrler.getHitObj` | 先判断是否相交，仅对相交攻击框继续创建交集矩形 | 候选攻击框顺序、实际命中的 `hitVO`/`hitRect`、后续判定和伤害处理 |

后两处针对战斗过程中的短寿命矩形分配。`getHitObj` 在命中时会多执行一次布尔相交计算，收益取决于未命中比例，不能仅凭分配减少保证加速。已核对当前播放器 `player/core/src/avm2/globals/flash/geom/Rectangle.as`：两种方法采用相同的空矩形及坐标重叠算法；未通过改变边界接触规则或减少检测次数取得性能。

没有修改原生帧率、角色 `nextFrame`/`goFrame`、招式命中帧、AI 更新频率、伤害、主动打击停顿、图片、音频或外部资源。动态残影/滤镜位图缓冲池仍只是[分析报告](bvn33-swf-logic-analysis-20261027.md)中的后续候选，不在本副本中。

## 修改和主机验证方法

以已安装验证过的离线版主 SWF 为输入，用 JPEXS 26.4.0 导出 P-code，定位 ABC 方法体，逐方法重新汇编；未重新编译整个 ActionScript 类。新文件再次解析并反编译为 ActionScript，确认上述条件分支与调用确实写入。

独立解析原文件与候选文件的全部 SWF 标签及四份 ABC，验证：

- SWF 版本 14、帧头、33 个标签的顺序和类型一致；仅第 4 个 DoABC 标签的内容变化。
- 所有常量池、方法签名、元数据、实例、类、脚本及方法体数量保持；其余三个 ABC 和所有非 ABC 标签逐字节一致。
- 仅下表四个方法体的指令改变。所有其他方法体逐字节一致；四个方法的声明栈上限、局部变量数量、作用域、异常表和方法体 traits 保持。
- 对原版及候选的四个实际方法体执行有限字节码控制流检查：分支目标均落在指令边界、局部变量索引合法、可达路径无操作数栈下溢/超限、合流栈/作用域一致、返回栈为空。这是结构检查，不是完整 AVM2 类型验证或游戏运行测试。

额外提取主 SWF 内嵌的 `fight_swf` UI 资源并反编译全部 33 个脚本。气槽数字 `fight_fla.qbar_txtmc_34` 和计时器数字 `time_txtmc` 均只在首帧注册 `stop()` 脚本；主游戏和该 UI 资源脚本未检出 `frameConstructed`/`exitFrame` 监听。不过省去同帧 goto 会减少帧生命周期事件，其他外部素材尚未全面核查，仍需验证档位变换、暂停恢复及多局状态。

398 个原外部资源（共 66,003,663 字节）在独立目录和 ZIP 内逐文件 SHA-256 校验一致；ZIP 的 CRC、401 个文件及全部解包内容校验通过。401 个文件包括主 SWF、398 个资源、使用说明和 SHA-256 清单。原离线主文件的最终 SHA-256 复核不变。
