# 死神 VS 火影 3.3：最新优化版 CPU 与功能删减评估

日期：2026-10-28。目标为 Pocket1 / LeafOS、GLES；使用掌机当前的脚本＋素材优化游戏及 A55/ThinLTO 播放器。**本轮没有删除游戏功能、修改 SWF 或安装新正式播放器。** 结论是删减候选与风险评估，尚无删减后的加速数据。

## 本轮最有价值的候选

优先试验将前景遮挡自动透明改为固定半透明。`MapMain.renderOptical → checkHitGameSprite` 只为前景装饰设置 alpha；它与战斗命中判定是两套调用。在本组脚本采样中，该调用树占主线程 CPU 样本约 **4.48%**，25 秒内执行 **17,772** 次遮挡检测。保留固定透明度可避免前景一直不透明时遮住人物；不应直接把它当作已经验证的游戏加速。

残影、闪光、镜头震动等可以成为可选的画面删减项，但本组残影只有 19 次位图捕获、约 0.26% 的 CPU 样本，不支持承诺关闭后会明显提速。动态滤镜位图本组没有调用，需用会触发该路径的角色及招式另测。不能把“没触发”解释成“开销为零”。

角色动画推进、碰撞、AI 和打击停顿应保留。角色时间轴还驱动动作、身体/攻击区域和帧脚本；碰撞决定命中；AI 决定 CPU 对手行为。打击停顿是游戏表现与时序，本组 `renderFreeze` 仅约 0.02% 的样本，取消它主要改变手感。

## 采样方法与限制

- 使用独立 HOME、配置和原生进度目录，游戏只读原目录。临时 Apps 清单使用明确调试名称，无正式系统/核心 `provides` 声明。
- 原播放器采集主线程 PC；临时诊断播放器在 AVM2 方法执行入口维护独立影子栈，并登记方法名称、ABC 索引及所属电影。1 ms 主线程 CPU 时间信号记录当时 PC 和调用栈，另计方法调用次数。诊断代码和预加载库仅放在忽略目录及设备调试目录，不进入正式安装。
- 同一一护/鸣人、魂/我爱罗、空座町，单人对 CPU；实战测量窗口在设备端自主起止，固定回放 `right,a,y,a,b,a,x,a` 八遍。两组各约 25 秒，测量日志均无选人、选图或加载切换，所有性能窗口目标 60 FPS 且未暂停。
- AI、动作、随机数、预热、CPU 频率和温度没有逐帧固定。影子栈查表、计数及采样本身也有成本，不能用两组 FPS 或 tick 的差异计算诊断开销或游戏加速比。
- 内核可能合并信号，配置为 1 ms 不等于每个样本精确代表 1 ms CPU 时间。PC self 样本和脚本包含子调用的样本是不同口径；脚本父子方法、功能组彼此重叠，不能相加，也不是删除功能后的预计 FPS 增幅。
- 约 64.74% 的诊断样本落在影子栈为空时，主要包含播放器外层帧生命周期和绘制等工作。不能据此称这些开销与游戏内容无关；本轮未逐个显示对象归因，不能量化“删除背景动画”的收益。优化后的直接本机调用、部分初始化路径也不等于完整 AS3 跟踪。

## 游戏函数与功能重要性

以下为脚本诊断组，分母是该组全部 4,935 个主线程 CPU 样本，包含相应方法的子调用。

| 函数 / 功能组 | 样本占比 | 本轮调用观察 | 删减判断 |
| --- | ---: | --- | --- |
| `FighterMC.renderAnimate` | 11.35% | 角色动画组整体约 13.90%，`renderChildren` 调用 1,324 次 | 重要；推进主动画、子动画、身体/攻击区域及延迟跳帧，不直接跳过 |
| `MapMain.renderOptical` | **4.48%** | 1,481 次；内部 `checkHitGameSprite` 17,772 次，后者包含于前者 | 首选实验；前景固定半透明，取消逐物件遮挡检测，不改战斗碰撞 |
| 战斗 UI 组 | 2.86% | `FightTimeUI.render` 1,481 次；气槽 `InsBar.setProcess` 2,962 次 | 血量、气量、计时很重要；此前数字重复重建补丁仍在，不能把整个 UI 当装饰删除 |
| 碰撞相关方法组 | 2.86% | 含身体/攻击/交叉检查，不代表所有物理成本 | 重要；不能减少判定或删除命中框，优先保持规则的实现优化 |
| `FighterAILogic*` 组 | 1.97% | 同一默认 CPU 对手样本 | 重要；停用或降频会改变对手反应，本组收益不足以优先牺牲玩法 |
| 普通/闪光等效果视图组 | 0.71% | 不含残影，包含相应效果更新的子调用 | 可选画面精简；本组贡献小，需保留移除回调、生命周期及技能相关对象 |
| `ShadowEffectView` | 0.26% | 4 次创建、93 次 render、19 次 `addShadowBp` | 可关闭残影；本组捕获少，不能承诺大幅提速 |
| `BitmapFilterView` | 本组未采到 | 无方法调用计数 | 未覆盖；需选会触发滤镜的招式，不能归为已证实热点 |
| `EffectCtrl.renderFreeze` | 0.02% | 1,436 次 | 保留；取消打击停顿主要改变手感与时序 |

`MovieClip.nextFrame` 调用树单项约 12.48%，与角色动画等行重叠。即使仅看似“子动画”，帧脚本仍可能启动技能对象或效果，不能把 `FighterMC.renderChildren` 整体替换为空。

原播放器 `/proc/<pid>/task/*/stat` 的同一约 25.48 秒区间中，主线程占进程线程 CPU 增量约 78.39%，`cpal_alsa_out` 约 7.77%，`threaded-ml` 约 4.51%，Mali 后端线程约 7.31%。音频输出线程包含混音/输出，不能全算成 BGM 解码，也不能把主循环 `audio_ms` 当作全部声音成本。关闭 BGM 或音效需单独 A/B；仅调音量为零未必停止解码，当前不将它列为优先大收益项。

## 后续实验次序

1. 单独制作前景固定半透明副本，保持碰撞、AI、角色帧和特效原样；核对遮挡、场景切换、暂停恢复，再做相同窗口对照。4.48% 只是本组调用树占比，不是可保证节省的时间。
2. 在明确卡顿的招式中统计残影和动态滤镜，再决定关闭、降低捕获频率或复用有上限的位图缓冲。普通命中特效已有缓存，本组不支持笼统删除所有特效。
3. 可另测背景装饰的静态化，以减少外层显示树/绘制负担；先区分纯装饰与镜头、地板、碰撞及帧脚本。本轮没有这个维度的对照。
4. 修复默认画质的入口覆盖后，重新验证首次 LOW、手动切换、APPLY 和保存重开；该修复与功能删减分别记录，避免混淆收益来源。

## 清理、用户数据与证据

测试进程已退出，临时 Apps 入口归档到调试目录的 `completed-test.pak`，应用和搜索索引已核验无该入口。必要时只清理已确认不存在的本轮入口，保留其他应用；内核没有本轮新增 OOM/杀进程记录。正式播放器未加载采样器。随包游戏仅更正使用说明和对应校验清单/manifest，不改 SWF 或 398 个资源，也没有更新设备上的游戏说明、安装包或 GitHub Release。
