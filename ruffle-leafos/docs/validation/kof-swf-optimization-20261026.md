## 修改范围

处理器为 [optimize_swf_bitmaps.py](../../scripts/optimize_swf_bitmaps.py)，使用 Python 标准库，依据固定 Ruffle SWF 读取器和 [Adobe SWF 19 规范](https://open-flash.github.io/mirrors/swf-spec-19.pdf)处理二进制标签，不重新编译脚本。

- 支持 AVM1 的 FWS/CWS 输入，修改 `DefineBitsLossless2` 调色板/RGBA 位图及 `DefineShape` 1—4 位图填充，包括新样式记录和嵌套 Sprite。
- 只裁掉 RGBA 四通道都为零的外边，保留一像素零色边界用于纹理边缘采样；裁剪原点准确补入填充矩阵，**不缩放、量化或降低颜色精度**，形状几何及命中区域不变。
- 导出给脚本、直接放置或可能被按钮/形变引用的位图保留原样；不裁剪重复平铺纹理；补偿不是整数 twip 时跳过。按钮/形变引用采用保守排除，可能多跳过一些素材。
- 仅合并引用可完整重写、宽高/编码类型/解压像素数据相同的私有位图。未知或不支持的结构报错，不以猜测的偏移写入。
- 游戏逻辑、音效、文字、原作者介绍、时间轴和原生帧率保留。该轮播放器仍有全库扫描及 Vulkan 同步开销，单改 SWF 不能替代播放器优化；当前回收与内存实现见[工程实现](../implementation.md#渲染资源与内存)。

## 使用与复现

原文件保留，本轮已将优化副本作为独立游戏放入 `Roms/flash/` 供试玩。内容指纹不同，播放器会识别为另一款游戏，原版进度不会自动沿用；新文件名也使用独立按键配置。此次没有迁移用户数据。

在仓库根目录执行，输出和报告都必须指定尚不存在的独立文件：

```powershell
python ruffle-leafos/scripts/optimize_swf_bitmaps.py "flash-transfer/fighting-games/拳皇Wing1.91.swf" --output "outputs/my-swf-test/拳皇Wing1.91-素材优化版.swf" --report "outputs/my-swf-test/optimization.json"
python -m unittest discover -s ruffle-leafos/scripts -p test_optimize_swf_bitmaps.py -v
```

后续若需要量化提速，应先使场景选择和输入序列可重复，再以同一播放器、接口、画质、角色、背景及预热条件比较原版/优化版，记录画面提交速率、Flash 帧推进、解码/上传时间及多局 RSS。
