# 死神 VS 火影 3.3：显示树遍历优化验证

日期：2026-10-27。目标为 Pocket1 / LeafOS、GLES 高画质；沿用未修改的 3.3 离线目录版。主 SWF SHA-256 仍为 `148592ba6fbffc79938660997ff8ae6d38c4f90d962208c46c41626199a9a4f5`。

## 定位和修改

对已安装 `011e51f57b165f95d793c5e0a5ac66bde504e63ef4f3c47032c9b8744ff60fd8` 主线程配置 1 ms CPU 时间信号采样，实战得到 8,629 个 PC。使用保留符号的对应构建解码，已核对其 `.text` 地址、长度与 SHA-256 和原二进制完全相同。内核可能合并计时信号，样本不是精确的逐毫秒计数；只统计采样落点，不是包含子调用的完整调用树。

实战 self 样本中，MovieClip::construct_frame 约 21.22%，OrphanManager::each_orphan_obj 约 13.20%，DisplayObject::run_frame_scripts 约 10.71%，容器 raw_container 约 6.64%。脚本可触发这些本机函数，不能把采样在解释器之外理解为与脚本无关，也不能将 Enter 全部解释为纯字节码时间。

本轮仅保留三类改动：

- RenderIter 先取得子列表的 Rc 快照，长度直接读同一快照，减少一次容器动态分发和借用；前向/反向迭代及回调修改列表的快照语义保留。
- MovieClip 直接借用当前 shared SWF 检查 AVM 类型，避免克隆 Arc 再立即释放。它仍读取当前 shared，不缓存跨加载/替换失效的旧标志。Graphic 已有 AVM2 对象时提前结束纯检查。
- 为默认帧脚本方法及生成的 enum 分发提供 inline 提示，保留所有分支、帧事件、对象和回调顺序。

没有改游戏 SWF、角色/AI/战斗算法、画质、目标帧率、CPU 频率、GC 或纹理缓存寿命。PC 采样库仅在隔离测试中预加载，不进入正式包。
