# 死神 VS 火影 3.3：外壳警告与离线目录副本

日期：2026-10-26。目标：Miniloong Pocket1 / LeafOS / ARM64 / Mali-G52，使用已安装的 Ruffle Flash 0.7.0。此记录不扩大其他设备、角色或长期兼容性结论。

## 结果与使用

本地离线目录副本已安装在 `Roms/flash/死神VS火影3.3-离线版/`。刷新 Leaf 游戏列表后，打开目录内 `死神VS火影3.3-离线版.swf`，使用 OpenGL ES。必须保留旁边 `assets/` 的完整层级。所有 398 个资源逐字节保留，主 SWF、资源和说明共 400 个文件。

隔离实机已进入一护对鸣人的实际战斗，并验证实体输入、暂停恢复及正常退出。正式 Flash 入口另行通过更新提示、主菜单及退出检查。仍存在脚本与 MP3 解码告警，不能据此承诺所有角色、变身、模式、多局或长时稳定性。

本地完整 ZIP：`outputs/bvn33-diagnosis-20261026/死神VS火影3.3-离线版.zip`。解压得到的整个游戏目录放入 SD 卡 `Roms/flash/`。这是本地适配副本，游戏不进入 Git、应用包或 GitHub Release。

## 原因与证据

原文件启动后显示 `WARNING`，下一行被截断为 `No running in a loa…`；trace 完整文本为 `[FC] No running in a loader.`。反编译后，同一语言项的中文为“不允许加壳运行”。因此应解释为游戏禁止以外壳方式运行，修正初次排查时“缺少加载器”的解释。

原 CWS 中 `DefineBinaryData` ID 3 原样包含 69,431,196 字节的 FWS 游戏。它与 [naptestdev 的独立 3.3 镜像](https://github.com/naptestdev/bleach-vs-naruto-3.3) 下载文件逐字节一致。该镜像不是官方新发布；这里只用于交叉核对游戏本体，不能单凭下载成功认定 Pocket1 可运行。

直接提取本体后，游戏通过外壳检查，进入头像与地图加载，但两个后端均在加载末段 OOM：

| 单文件会话 | 内核证据 |
| --- | --- |
| GLES，PID 8070 | `Killed process 8070 (ruffle)`，anon-rss 564,732 KiB / file-rss 256,780 KiB |
| Vulkan，PID 8256 | `Killed process 8256 (ruffle)`，anon-rss 482,692 KiB / file-rss 356,224 KiB |

这里是系统结束进程，与原文件主动显示警告属于两个阶段的问题。RSS 分类不能简单视为纯 GPU 内存，也不据此断言切换后端能消除内存不足。

## 副本变更边界

游戏本身同时含有 `ZipAssetLoader` 和默认外部目录 `AssetLoader`。本地副本采用后者：

1. 从本体 `DefineBinaryData` ID 222 提取原始 ZIP，保留 398 个文件的路径与字节。原 ZIP 共 407 个条目，另 9 个为目录；资源总计 66,003,663 字节。
2. 仅将 `bleachvsnaruto.initlize` 中创建并安装 `ZipAssetLoader` 的 19 字节直线指令替换为 NOP。栈净变化保持零，继续使用 `AssetManager` 已有的默认外部加载器；战斗类方法不作修改。
3. 将内嵌 ZIP 数据换为空 ZIP，移除主 SWF 对大资源包的持有；完整内容改从相邻 `assets/` 按原路径读取。缩小后的文件不能继续使用原 FlashCore 的封装校验，因此直接把根类绑定到原游戏 Sprite `bleachvsnaruto`，顶层定义合并到单帧。只移除顶层帧标签和多余 ShowFrame，不改变嵌套角色时间轴。
4. 主 SWF 使用 CWS 压缩；图片、声音、角色 SWF、配置、游戏原生帧率及战斗逻辑保持。播放器源码、二进制、渲染策略与用户既有设置未修改。

上述是游戏打包与启动适配，不能描述为完全未改脚本的原版，也不能把“仅原样提取”这一失败候选当作最终安装副本。

## 验证范围与限制

- 主机：安全相对路径、ZIP CRC、398 个资源逐文件 SHA-256、主 SWF 标签与指定指令范围检查通过；JPEXS 26.4.0 解析、反编译复核通过。完整 ZIP 400 个文件及解包内容校验通过。
- 实机安装：398 个资源与主 SWF 的 SHA-256 再次核对通过；完整目录包含额外使用说明。Leaf 需要刷新游戏索引，未索引的新文件可能在启动请求中返回 `ROM path missing`。
- GLES 隔离会话：约 19:47–19:53，标题、更新提示、单人对电脑、选择一护/鸣人及魂/我爱罗援助、空座町场景、战斗、移动/攻击/跳跃输入、暂停恢复和正常退出；观察到实战两次 RSS 为 593,220 / 593,924 KiB，约 579–580 MiB，只是离散观察。
- 该会话没有新的内核 OOM 或资源 `LoadNeverCompleted`，但有 17 条 `TypeError: Error #1006: value is not a function.` trace，其中 9 条附 `GameMainLogicCtrler.renderGameSprite`；后者包含在总数中。游戏继续推进并正常退出，但这些错误对招式、渲染和全部角色的影响尚未定位。另有 MP3 junk / main_data_begin 告警；未做人工听感验收。
- 正式通路：刷新索引后，通过 Leaf Flash 分类、安装的正式播放器和 GLES 启动新副本，核对更新提示、主菜单及 `progress_flushed=true` 正常退出。没有把隔离 Apps 会话当作正式游戏通路证据。
- 原 3.3 文件、正式播放器及原有配置/进度前后校验一致。隔离测试没有变更正式用户数据；正式验证仅新增此副本的内容目录元数据，未改动既有文件。原单文件和其他游戏保留，失败的临时单文件与 Apps 入口已归档。
- 最终目录版尚未验证 Vulkan、广泛角色、变身、其他模式、多局与长时稳定性。原生进度按内容身份区分，新副本不会自动继承旧单文件的进度。

本轮没有修改或重新构建播放器，因此不报告新的 ARM64 编译或前端主机回归结果。此处的主机验证是游戏结构、资源与归档检查。
