# 0.8.5 ZIP 加载验证（2026-11-02）

## 范围

安装包将随包死神 3.3 和 3.6 各自打成一个 ZIP，保留主 SWF 和原 `assets/` 相对路径。播放器以归档 SHA-256 作为缓存键，首次显示加载文字与进度条并解压，随后从缓存读取；主 SWF 内容仍决定原生进度身份。旧目录按键方案仅在旧记录确认内容和路径身份且 ZIP 尚无方案时复用。缓存校验检查所有文件存在和大小，以及主 SWF CRC；其他资源的同大小损坏不能检出。游戏结束后可手动删除缓存重新解压。

## 构建与主机检查

- ARM64 release 构建通过；播放器 ELF SHA-256：`f4dc303617ac116e29f8f61824b685986980db2d16add3427fc13c24e4e4c233`。构建输入摘要：`197439fc063982be0693c972b6eccf798424fbb58f069d02fc3c0f7060b8cb35`。
- 前端会话 153 项、ZIP 提取与缓存 3 项、打包 5 项、发布脚本 15 项通过；构建输入 24 项通过、1 项因 Windows 缺少创建符号链接权限跳过。
- 打包校验全部 959 个源文件，安装归档中仅有拳皇 SWF、死神 3.3 和 3.6 ZIP 三个 ROM。两个 ZIP 分别包含主 SWF 和 398 / 554 个资源；内容逐项核对源清单。传入设备的两个 ZIP 与安装归档中同名 ZIP 的 SHA-256 一致，分别为 `2c807833a0f629478b7fd87e988e965c7cfdcc3112471c333434396fb15b054f`、`b6f85e4795b1a0fe739de088c802cfe3b70b9575af92908727df4707e7ed76b6`。
- Windows 本机的启动脚本 dry-run 因 BusyBox / Windows 中文路径编码不一致而未完成；该项不计为通过。

## Pocket1 隔离启动

使用上述 ELF、独立测试应用及隔离存档、按键和缓存，未覆盖正式应用与游戏。3.3 冷启动从播放器启动到 ZIP 准备完成约 3.90 秒、到首个 GL swap 约 5.90 秒；同一 ZIP 的缓存复用一次分别约 1.54 秒和 3.23 秒，进入游戏并正常结束。此处的准备时间包含哈希与解压/校验，不与上轮单独测量的 `unzip` 时间直接等同。

3.6 冷启动 ZIP 准备完成约 12.43 秒、首个 GL swap 约 14.23 秒；设备截图确认中文“正在加载游戏…”及进度条，随后进入游戏自身的资源加载画面，正常退出。此轮未验证 3.6 战斗、完整游戏流程、正式安装或 Leaf 对新版 ZIP 的实际扫描。时间各为单次样本，取自设备运行日志和启动计时，受缓存、存储和设备状态影响。

此前目录与 ZIP 解压缓存的 3.3 同场景约 30 FPS 比较属于独立实验，方法及样本见 [ZIP 与目录实机对照](zip-vs-directory-20261102.md)；不能扩展为本次所有游戏和场景的帧率结论。
