## 离线适配与脚本修改

主文件拆出原保护壳中的核心 ABC 和嵌入 UI，保留其符号映射，替换根启动类。新增独立的启动、普通外部资源加载、SharedObject 存档/日志适配、特效缓存处理和启动壳身份兼容类；原保护壳的舞台/LoaderInfo 别名仍按游戏使用方式初始化。原 Windows JSON 存档结构通过 SharedObject 保存，内容身份及存档路径独立，不自动继承 3.3 或 Windows 的 `bvnsave.sav`。日志适配避免原 `Loger` 类的 AIR 文件类型依赖阻断启动。

对原 4,155 个核心方法只修改下列 12 个方法；其余 4,143 个方法体保持原字节。新 QName 只追加，旧常量索引、原方法签名、类/脚本记录、方法头和异常记录保持。JPEXS 在汇编时会将少数原 Multiname 签名改为追加的 QName；生成流程恢复原 `method_info`，再用独立 ABC 读取器逐项核对。

| 方法 | 修改目的 |
| --- | --- |
| `launch.initlize` | 入口默认画质改为已有的 LOW，使用普通日志适配；保留后续读取已存设置 |
| `AssetManager.init` | 加载已还原的普通 `assets/`，避免运行时再解密 |
| `GameInterfaceManager.saveGame` / `loadGame` | 用 SharedObject 替代 AIR 文件存档 |
| `JoySticker.initlize` | 在平台不支持原生 GameInput 时也初始化空设备容器，保留键盘输入路径 |
| `FightTimeUI.render` | 数字未变化时不重建计时显示 |
| QiBar 内 `InsBar.setProcess` | 目标帧变化才 goto，同帧 stop |
| `FighterAILogicBase.targetInRange` | 布尔范围检测避免临时交集矩形 |
| `GameMainLogicCtrler.getHitObj` | 先排除不相交候选，命中才创建原交集对象 |
| `EffectModel.cacheEffects` | 按原枚举顺序分次执行原缓存方法，再裁剪缓存图像的透明边缘 |
| `MainGame.initlize` 内 `loadGameBack` 闭包 | 将原完成事件和回调移到全部特效缓存完成之后 |
| `GameInterfaceManager.afterBuildGame` | 跳过三处 AIR 专用 `cacheAsBitmapMatrix` 赋值，保留普通地图绘制及原背景缓存设置 |

四项战斗/UI 优化沿用 3.3 的处理原则，但重新按 3.6 的类、方法和指令上下文定位。12 个原始/候选方法的指令边界、分支、栈合并及声明的局部变量/作用域/栈容量检查通过；这不是完整 AVM2 类型验证。

原 `win_ui` 的 RSL 预加载器依赖联网获取 TLF。下载 [Adobe 原始签名包](https://fpdownload.adobe.com/pub/swz/tlf/2.0.0.232/textLayout_2.0.0.232.swz)，验证 CMS 签名并提取 SWF，其 SHA-256 为 `8f903698240fe799f61eeda8595181137b996156bb176da70ad6f41645c64c74`，与游戏内置摘要完全相同。将该库的 ABC 放入解出的 UI 内容电影，替换外层联网预加载壳；内容电影的原标签、脚本和时间轴保持，不再等待旧站点下载。另查到的 SDK 镜像与该指纹不同，未用于交付。最终主电影、离线 UI 和原始库均通过 Ruffle 解析。

保留原整批特效预缓存的候选曾在开始战斗时触发 OOM。修订后每种特效之间让出执行，仍调用原 `EffectVO.cacheBitmapData`，保留全部动画帧槽、帧标签、比较去重和完成顺序；之后仅裁去透明边缘并补偿偏移，保留一像素透明余量。诊断 `diag4` 检查 65 个特效、560 个独立缓存帧对象，实际裁剪的图像均还原到原尺寸并逐像素比较通过，未裁剪对象保持；缓存像素等价值为 80,807,500 → 54,650,272 字节（约 77.06 → 52.12 MiB）。交付版关闭额外还原校验，处理路径一致。该数字不是进程总内存降幅；旋转、全部招式的实机视觉仍需扩大覆盖。

## 素材与保护标签

按游戏自身的 Hex 转换、20 字节密钥扩展和 CBC 分段方式还原全部 554 个资源，每个文件重新编码后与原加密文件一致。图片、声音和 SWF 的首尾分段及未加密中段分别保留；XML/JSON 只去除编码产生的尾部零填充，原配置内容保留。`map.xml` 的原装饰注释包含连续连字符，主机 XML 检查只在解析副本中移除注释，没有改写交付文件的内容。

外部 SWF 统一为标准 CWS 容器，正常电影的原标签负载和时间轴不变。公共 `effect.swf` 另有大量保护用短记录，原样副本无法通过严格解析：在核对 SymbolClass、放置、填充、按钮状态、字体和声音引用后，清理 1,626 个保护记录，未删除有引用的定义；保留其余标签的负载、顺序、脚本、声音、放置，以及保留 Sprite 的 ID/声明帧数，并补齐隐式结束标记。清理前后独立展开比较通过，清理后 Ruffle 解析通过。不能把这种特定来源的清理规则当作通用 SWF 修复器。

对主电影、外部电影和嵌入 UI 的 ABC 检查未发现 `readGraphicsData` / `GraphicsBitmapFill`，再启用现有私有位图保护规则。此静态检查不证明不存在动态拼接的属性名。

- 130 个资源 SWF 中 105 个应用裁剪或去重，共裁剪 15,580 张私有无损位图，合并 1,407 个重复定义。
- 全资源无损位图累计展开等价值约 2,832.90 → 1,518.17 MiB，减少约 1,314.73 MiB。这是各素材的静态合计，不是同时驻留内存、实测 RSS 降幅或 FPS 提升比例。
- 21,043 个原始位图定义逐行还原/逐像素比较、23,267 个形状及 34,841 个填充变换检查通过；素材 ABC、符号、声音、放置和时间轴负载保持。
- 424 个非 SWF 资源与还原后输入逐字节一致。9 项既有位图优化器保护回归通过；原始/候选及主文件共 261 份电影通过固定 Ruffle SWF 解析器。
