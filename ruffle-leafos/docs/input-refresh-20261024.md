# 2026-10-24 连发、音量与菜单输入修复

基线 0.6.3，设备 192.168.5.4。按功能更新记录并提交，最终统一构建、安装和真机验证。

## 1. 每个按键独立连发

交互：在“编辑当前映射”的原有五列宫格中选中一个实体键或摇杆动作，按 Y 循环“关闭 → 慢速 5 次/秒 → 标准 10 次/秒 → 快速 15 次/秒”。启用后该格子直接显示“连5/10/15”，底部显示完整频率；无需进入子菜单。默认全部关闭。只在按住实体键或保持摇杆方向时连发，松开停止。

范围：键盘、组合键和鼠标左右键可启用；鼠标移动、速度修饰、拖拽锁定等连续/切换动作不提供连发。每个键、每个游戏、每个按键方案独立；Y 只改编辑草稿，仍需本次应用或保存。X 恢复该键时同时关闭其连发，整套恢复也全部关闭。M+X 互换方向时连发随对应动作互换，摇杆按下独立保留。

实现：独立的单调时钟调度器，每次先按下，再按频率交替松开/按下；沿用输入所有权计数，避免连发松掉另一实体键仍持有的同一键或修饰键。暂停、切换方案、方向互换、失焦、断连或 Menu 组合键会取消旧连发并释放输入。卡帧后不补发堆积事件，实际频率受游戏处理帧率限制。

格式：新保存为 v5，新增 14 项 turbo 和 5 项 axis-turbo；v1—v4 继续可读且连发默认关闭，不自动改写旧文件。原两个默认方案及全局光标配置不变，详见 [按键格式 v5](controls-format-v5.md)。

验证：67 项主机测试和 ARM64 cargo check 通过，覆盖逐键/逐方案保存重开、旧 v4、格式拒绝、Y 状态与 X 复位、方向互换、频率、松开终止、共享修饰键以及卡帧不突发。真机操作与截图列入最终验证。

## 故障调查基线

音量：在原 0.6.3 上注入物理音量键，Leaf platform-levels 显示 0→5→0，系统音量处理本身正常；源码确认独立模拟器会跳过系统音量 OSD。用户最近游戏日志为《闪客快打3-优化版》，游戏内音量 100%、未静音，走 Leaf PulseAudio。

菜单：原版探针与《闪客快打3》两种松开顺序各重复测试，暂未稳定复现。用户补充：多个游戏均可能出现，游戏继续运行，再次 M+A/B 后可恢复。因此后续修复要解除菜单对组合键后虚拟按键释放/持有状态的依赖，并验证短按、长按和不同松开顺序，不能把普通路径通过当成已复现根因。


## 3. Menu 与映射切换独立处理

用户补充：多个游戏出现，游戏仍运行，再 M+A/B 可恢复。修复将菜单唤起从 SDL 虚拟 Guide 的持有/松开状态中独立：使用专用只读状态观察线程，每 4ms 查询 EVIOCGKEY/ABS，记录物理 Menu 与其他按键的状态变化及单调时间，游戏主线程稍后消费队列。不会因 SWF 长帧错过一个完整的短按，也不需要等待虚拟 Guide 的释放来重新触发。

短按 Menu 松开时触发一次；M+A/B、M+X、M+十字下保持原行为且不附带菜单。其他按键/音量/摇杆参与过的组合以及启动时已按住 Menu、三秒长按均不生成短按菜单。Leaf 仍负责系统快捷键和长按逃生。物理观察可用时忽略重复的虚拟 Guide；不可用时回退 Leaf 事件，Guide 也不再占用游戏 held 集合。组合键触发还会阻止排队中的动作键泄漏到游戏。

观察线程只查询按键和方向状态，不读取被 Leaf 独占的事件流，不抓占设备、不写输入、不更改系统映射；退出时结束线程。69 项主机测试及 ARM64 cargo check 通过，新增两种松开顺序、完整快速短按排队、系统组合取消、启动按住和长按不误触测试。原版普通复现未稳定触发用户故障，最终真机需要重点验证这条新通路。


## 2. 系统音量与游戏内反馈

已确认物理音量键由 Leaf 接收，并能改变 PulseAudio 的真实系统音量。Ruffle 属于独立模拟器会话，Leaf 按 KMS 模拟器策略不显示系统音量条，而 Ruffle 实际使用 Wayland，导致反馈缺失；不应再把物理键叠加处理一次。

实现：读取物理音量键后，通过后台工作线程读取 Leaf 的 platform-levels，游戏右上角显示真实“系统音量 N%”。长按更新，松开约两秒消失；若当前游戏在播放器内静音或音量为零，同时标明“游戏静音”。游戏/暂停界面均能显示。只读取系统音量，不重复增减、不改写每游戏音量配置。M+音量仍交给 Leaf 调亮度，不当作普通音量操作。IPC 有 200ms 超时和回复长度上限，游戏线程不等待 socket，不拿猜测值冒充实际音量。

验证：71 项主机测试及 ARM64 cargo check 通过，覆盖真实回复字段、重复/越界/空值拒绝，节流和 M+音量排除。实际声道、音量条与菜单恢复在最终真机步骤验证。新增仅供诊断的 --trace-input，方便验证连发的真实按下/松开事件，正式启动不启用。


## 新地址复核与补充修正（2026-10-24）

用户更新设备地址为 10.110.72.12。电脑 WLAN 为 10.110.72.135/24，但新地址的 ADB 5555 端口连接超时，无法读取当前安装版本或继续真机验收。上一次确认的正式安装为 0.6.3；0.6.4 尚未正式安装通过。

复核上一轮失败的按键测试发现：Leaf 的输入代理对物理设备使用 EVIOCGRAB，因此另开的只读 evdev 事件客户端收不到事件。旧候选实现误认为事件监听可用而忽略虚拟 Guide，导致测试不能打开编辑菜单，连发验证也因此未能执行。这是候选版回归，不能记作三项功能已完成。

本次改为专用线程每 4ms 查询物理按键状态，仅在 Menu 相关时额外查询方向状态，将变化排队交给游戏线程；EVIOCGKEY/ABS 不受 Leaf 的独占事件读取影响。保留已有启动/长按/组合键排除与 SDL 回退。不修改 Leaf 输入代理，也不解除系统抓占。

当前验收状态：逐键连发、系统音量反馈和菜单独立处理代码已实现，71 项主机测试及 ARM64 release 构建通过；新的采样实现、真实连发、保存重开、系统音量条及快速组合键后 Menu 恢复仍待在新地址上验证。上轮 ARM/GLES脚本回归通过只代表当时的普通脚本通路，不代替本轮物理按键验收。
