# Flash 数据管理目录格式

目录记录位于原生进度根目录的 `slots-v1/catalog/<内容指纹>.meta`。它保存用于显示和关联的元数据，不是游戏是否有数据的依据；可管理条目必须实际存在存档、按键方案、方案选择记录或其备份，包括损坏文件。只有目录记录、内置默认或已清理归档不生成列表条目。

## 文件身份与关联

- 文件名的内容指纹由 SWF 字节计算：两个 16 位十六进制 FNV-1a 64 位值分别对应原字节和逆序字节，再接 `-<十进制字节数>`。它与 `slots-v1/games/<内容指纹>/` 的存档目录一致。
- 按键路径标识是 16 位十六进制 FNV-1a 64 位值，散列输入为按键文件完整 `identity` 的十六进制文本。标准 ROM 路径先归一为 `flash/<相对路径>`，再按 UTF-8 字节编码为 `identity`。它对应 `controls/slots/<路径标识>/` 与旧 `controls/games/<路径标识>.rmap`。
- 存档按内容识别，按键按路径识别。同一路径的不同 SWF 版本可以关联多组内容存档；相同内容在不同路径启动时，目录记录保留最后一次登记的路径。列表清理目标按明确关联的标识生成，不按标题猜测，也不让同一数据目标出现在多个条目中。

## 行字段

文件使用 UTF-8 文本，新写入三行，每行以换行结束：

```text
<游戏标题>
<按键路径标识>
path=<绝对 SWF 路径的 UTF-8 字节的小写十六进制编码>
```

| 行 | 内容与限制 |
| --- | --- |
| 1 | 游戏标题；写入时将回车、换行替换为空格。标题只用于显示，读取时过滤控制字符并最多保留 256 个字符。 |
| 2 | 按键路径标识，16 位十六进制。与按键文件 `identity` 的散列对应。 |
| 3 | 可选路径字段，固定前缀 `path=`；保存未经过 URL 转义的文件系统绝对路径。编码前 UTF-8 长度最多 4,096 字节，不接受控制字符及 `.`、`..` 路径段。无法编码时不写路径值。 |

读取兼容旧的“标题 + 按键路径标识”两行文件；没有第三行不表示文件损坏，也不会仅为读取自动补写。整份元数据读取上限为 64 KiB。新路径还须属于启动环境允许的 Flash 根目录、扩展名为 SWF，并与第二行标识一致；不符合条件的路径不用于定位游戏。

## 路径状态与失效标记

新路径字段优先用于定位；旧记录可从实际按键文件的 `identity` 恢复 `flash/<相对路径>`，再结合启动环境提供的 Flash 根目录查找。映射损坏时，仅在可恢复唯一 identity 且散列与目录标识一致时将其作为路径线索，不因此把映射视为有效。

存在已知路径但找不到可访问的普通 SWF 文件时，条目显示“已失效 / Unavailable”，数据继续保留供清理。路径未知的历史记录不直接标为已删除；仍可通过实际数据文件管理。状态检查只判断文件存在性，不读取或验证当前 SWF 的内容指纹，因此同一路径替换了 SWF 时不会据此判定旧存档已匹配新内容，也不会自动迁移存档。
