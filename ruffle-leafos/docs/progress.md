## 已实现

### AisOS 实机验证

`pocketais` 分支增加独立 GitHub Actions 安装包，接入实体 Home 作为 Menu，并在按键编辑中加入右摇杆四方向及按下。在 `f820f3-20261020` 上读到 `KEY_HOME=102`、`ABS_RX`、`ABS_RY` 和 `BTN_THUMBR`。这台设备的默认与当前 RGBox 清单及 EmulationStation 清单均无 Flash 分类，游戏通过 Ruffle Flash 应用内部列表打开。[当前安装与操作](../README.md#aisos-应用菜单)

2026-11-19 验证 GitHub Actions 生成的 `ruffle-pocketais-0.8.6.zip`，核对 SHA-256 和安装文件权限。将产物解压到掌机临时目录，用设备输入节点发送按键事件。应用列表可以启动 Bloxorz 和 ZIP 显示探针，两者均用 GLES 运行，保存并退出后回到列表。Home 短按打开和收起暂停菜单，Home 组合键可以切换按键方案、交换十字键与左摇杆、开关鼠标拖拽和调节亮度。右摇杆四个方向及 R3 的五个独立映射均收到对应的按下和松开。测试后亮度恢复原值，新版按键尚未手按复核。[打包运行记录](https://github.com/changdy/ruffle-leafos/actions/runs/44550634161)

2026-11-20 用新 GitHub Actions 产物在同一台掌机临时运行。通过设备输入节点验证 Fn 在子目录、暂停菜单、按键与画面设置、数据管理中逐级返回。游戏中按 Fn 会选中保存并返回游戏列表，待 A 确认。通过列表的 Y 进入数据管理，用临时数据验证取消后原存档仍在、确认后单游戏存档和批量按键配置分别移入本地备份目录。完成了游戏列表、暂停与设置页面、数据管理及清理确认页的 1024×768 实机截图。[打包运行记录](https://github.com/changdy/ruffle-leafos/actions/runs/44558943131)

同日验证统一菜单样式的安装包。实机截图确认游戏列表、暂停、按键设置、画面设置、数据管理和清理确认页均使用同一组背景、分隔线、焦点和底栏颜色。列表的 Fn 退出提示完整显示。通过设备输入节点复核暂停后继续、确认退出、逐级返回和测试数据清理。[打包运行记录](https://github.com/changdy/ruffle-leafos/actions/runs/44565418371)

#### 早期预览记录

RK3562 / AisOS community `f820f3-20261020`、RGBox、1024×768 内屏、Mali-G52 和 exFAT 外置游戏卡已验证。该预览包复用了项目 v0.8.6 发布的 ARM64 播放器。打包脚本校验发布包和 PySDL2 的 SHA-256，安装后的 9 个文件与交付 ZIP 逐字节相同。

从 RGBox「应用」打开 Ruffle Flash 后，通过设备输入节点发送手柄事件，以实际屏幕和会话日志核对。Bloxorz 用摇杆点击开始、跳过说明，切到方案 2，在第一关用十字键使 Moves 从 0 变为 1。注入逻辑 Guide 事件后打开暂停菜单，“保存并退出”返回列表。另从列表打开 ZIP 显示探针，确认解压缓存、GLES 彩块画面和返回列表，按 B 回到 RGBox。CPAL 成功打开双声道输出。音频听感、含有效 SharedObject 的跨会话读档与长时性能待验。该次测试使用逻辑 Guide 触发暂停。[安装与操作](../README.md#aisos-应用菜单)

按机身从左到右的顺序，每颗小键手动按两次。内置 `play_joystick` 的八次按下依次为 `464, 464, 102, 102, 314, 314, 315, 315`，确认四个位置分别对应返回（`KEY_FN`）、Home（`KEY_HOME`）、Select（`BTN_SELECT`）和 Start（`BTN_START`）。

按键适配后，在掌机上读取内置手柄的 SDL 绑定，确认 R3 对应 Guide、L3 对应摇杆点击，两个摇杆和 L2/R2 的六条模拟轴与系统配置相符。用进程内虚拟手柄向正式游戏列表输入原始按钮和轴值，在 18 项测试列表上验证双摇杆单步选择、保持倾斜时不重复移动、肩键跨页和末页边界、A 打开与 B 返回。新版安装包的全部 9 项与卡上文件哈希一致。本轮保留了正在运行的拳皇对局，实体 R3 的手按暂停和恢复待复核。

2026-11-19 在同一台掌机上从应用列表打开两个可选游戏 ZIP。打包时逐项核对主 SWF 和所有随附资源的清单哈希，复制后在卡上复核 ZIP 的 SHA-256。两款游戏均使用 GLES 和按键方案 1，每款在一段约 15 秒的对战中采集 11 次屏显 Flash FPS 和进程 RSS。

| 游戏 | 实机场景 | 屏显 FPS | 进程 RSS |
| --- | --- | --- | --- |
| 拳皇 Wing 1.91 | 玩家对电脑，草薙京对八神庵，确认连击和血条变化 | 33.4–34.5 | 452–497 MiB |
| 死神 VS 火影 3.3 | 小队街机战，完成选人、援助和出场排序，确认攻击特效、血条和倒计时推进 | 29.7–30.6 | 572–581 MiB |

两次“保存并退出”都回到游戏列表，日志均记录 `progress_flushed=true`。死神 3.3 首次启动出现特效加载等待，对战日志出现 `TypeError #1006` 和 MP3 解码告警。死神 3.6 定制版主 SWF 在本轮校验时被 Windows Defender 以 `Exploit:SWF/Rigved.A` 隔离，未安装或运行，检测原因待核实。

同一固件已安装独立的 Screen Color。通过 RGBox 应用菜单启动并注入内置手柄事件，验证实时预览、B 取消、A 保存和 X 恢复。内置 DSI-1 支持 1024 项 RGB Gamma 表。设备显示控制器读回暖色档 3 的末项为 R/G/B = 1023/1010/992，回到 RGBox 后保持该值。停止调色服务、手动恢复线性表后，重新启动服务能加载已保存的档位。预览进程被终止后，服务恢复了预览前的线性表。开机服务已注册，整机重启、休眠唤醒和其他固件尚未实测。[使用方法](../README.md#aisos-内屏调色)
